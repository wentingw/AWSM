# World Lobby 四轨迹对比

## 1. 固定输入与评测契约
- 以 [`vio-reconstruction/sessions/lobby_orb_success_20260929T123153`](vio-reconstruction/sessions/lobby_orb_success_20260929T123153) 为唯一会话：ViPE 读取与 `simulation_vio.mp4` 同源的原始 RGB 帧；OpenVINS 读取原始 RGB、250 Hz IMU 和 `inputs/calibration.json`；GT 仅在各估计器输出冻结后读取。
- ORB-SLAM3 直接复用已冻结的 [`stable_orbit_orb_success_20260929/frozen/camera.npz`](stable_orbit_orb_success_20260929/frozen/camera.npz)，并校验现有 SHA-256。
- 所有方法保留原生时间戳与缺帧，不插值填补；分别报告覆盖率，并以四方法严格共同有效时间戳作为公平指标主表。

## 2. 从头运行并冻结 ViPE / OpenVINS
- 复用现有 ViPE 默认流程与历史 provenance（[`stable_orbit_m2_vipe_default_20260929`](stable_orbit_m2_vipe_default_20260929)），建立隔离输出目录，对新 180 秒 RGB 从头运行默认 depth estimator，导出相机 `camera.npz`、日志、配置和哈希。
- 复用 OpenVINS runner [`stable_orbit_da3_rerun_20260923/code/openvins/scripts/run_openvins.py`](stable_orbit_da3_rerun_20260923/code/openvins/scripts/run_openvins.py)；将会话 FRD IMU/相机外参严格转换到 runner 需要的约定，先做短输入冒烟测试，再跑完整 180 秒并冻结轨迹与 provenance。
- 对两条轨迹执行时间单调性、旋转正交性、单位、覆盖区间和最终状态检查；失败时保留失败产物，不用 GT 调参。

## 3. 统一对齐、指标和 Figure 14(a) 风格输出
- 复用 Figure 14 源绘图逻辑 [`stable_orbit_da3_rerun_20260923/code/evaluation/plot_pose_comparison_vipe.py`](stable_orbit_da3_rerun_20260923/code/evaluation/plot_pose_comparison_vipe.py)，生成 GT、ORB-SLAM3、ViPE default、OpenVINS 的俯视/三维相机轨迹对比；显示时对共同区间均匀降采样，计算仍使用全部共同有效帧。
- 每个估计器仅做一次全局 SE(3) 刚性对齐、`scale=1`。主表记录共同帧数、原始覆盖率、ATE RMSE/median/P95/max、旋转 RMSE/median/P95/max；另列 Sim(3) scale 与 ATE 作为尺度诊断，不用于主排名。
- 输出 `trajectory_comparison.png`、逐帧误差 CSV、`metrics.json`、Markdown/HTML 表格、完整命令与输入/输出 SHA-256。

## 4. 验证与交付
- 检查四条曲线图例、坐标轴单位、视角与 Figure 14(a) 一致，验证主表全部来自相同时间戳集合，并对指标脚本做数值自检。
- 在 Cursor Canvas 中内嵌最终轨迹与指标，便于并排查看；同时保留静态 PNG 和机器可读 JSON/CSV。此次只生成本地结果，不修改或发布 Hugging Face 网页。
